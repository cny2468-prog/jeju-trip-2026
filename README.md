# 제주 2026 현장체험학습 안내

- 학생 안내: https://cny2468-prog.github.io/jeju-trip-2026/
- 교사용 수집 화면: https://cny2468-prog.github.io/jeju-trip-2026/teacher/

2학년 1~10반의 장소별 일정, 버스·객실 배정, 준비물과 유의사항, 소감문과 사진 콘테스트 제출을 제공하는 안내입니다. 교사 이름과 학생 제출 자료는 저장소에 포함하지 않습니다.

## 배포 구조

학생 안내와 사진·지도·스크립트는 GitHub Pages에서 제공합니다. `main`의 안내 파일을 수정하면 GitHub Actions가 자동 배포합니다. 교사용 주소는 로그인으로 보호된 수집 서버로 이동합니다.

사진·소감문 제출은 기존 Cloudflare Worker의 D1·R2에 저장됩니다. GitHub Pages는 정적 사이트를 제공하므로 이 저장 서버가 함께 필요합니다. 기존 제출 자료는 저장 서버에 유지되며, 비밀번호와 서버 비밀값은 GitHub에 넣지 않습니다.

- 안내 소스: `public/`
- Pages 빌드: `node scripts/build-pages.mjs`
- Pages 결과: `pages-dist/` (Git 제외)
- Pages 자동 배포: `.github/workflows/pages.yml`
- 서버 소스: `worker/`, `db/`, `drizzle/`
- 서버 빌드: `npm ci`, `npm run build`
- 검증: `npm test`

Pages 빌드는 `GUIDE_BACKEND_ORIGIN` 환경변수로 저장 서버를 설정할 수 있습니다. 기본값은 현재 운영 중인 서버입니다. 서버는 `worker/student-api.mjs`에서 지정한 Pages 출처의 학생 제출 API만 허용합니다. 교사 인증과 조회 API는 외부 출처에 열지 않습니다.

서버 코드를 고친 경우에는 저장 서버도 별도로 배포해야 합니다. Pages 자동 배포만으로 저장 서버 코드는 바뀌지 않습니다. 학생 안내의 작성 중인 초안은 브라우저·사이트 주소별로 저장됩니다. 이전 주소에서 작성하던 글은 그 주소에서 제출하거나 파일로 저장한 뒤 새 주소에서 불러올 수 있습니다.

## 사진 제출

큰 사진은 브라우저에서 자동 압축하며, 한 장소당 최대 10장입니다. 모든 반을 합해 동시에 최대 20건, 예약된 전송 총용량 최대 32MiB 안에서 전송하고 나머지는 자동 대기합니다. 큰 사진은 동시에 전송할 수 있는 수가 줄어듭니다. 전송 오류는 같은 사진 번호로 다시 시도해 중복을 방지합니다.

업로드 예약은 요청별로 한 번만 사용할 수 있고 전송 중에는 만료 시간을 갱신합니다. 대기 간격은 서버 안내에 따라 약 5~17초로 늘리며, 본문 길이가 없는 요청도 읽는 중에 용량을 제한합니다. 학생별·장소별 10장 제한은 저장 시점에도 확인합니다.

새로 제출한 사진은 교사 화면에서 긴 변 640px 이하의 별도 미리보기로 표시합니다. 이전 제출본은 기존 사진을 사용합니다. 원본 제출 파일 다운로드는 유지합니다. 콘테스트 후보 선택은 사진을 다시 불러오지 않습니다. ZIP은 묶음당 200MiB·1,000장 이하로 나누고, 묶음별 사진 수와 예상 용량을 보여 줍니다.

## 운영 전 확인

`node --test tests/capacity-review.test.mjs`는 30·100·300명이 동시에 시작해 각각 10장씩 보내는 서버 로직 시험입니다. 별도 메모리 SQLite와 파일 해시 저장소를 사용하며, 운영 D1·R2 성능이나 Cloudflare 계정 한도를 측정하지 않습니다. 운영 Worker의 메모리·CPU, 현장 통신망, 3일간 가용성은 이 로컬 시험으로 보장할 수 없습니다.

현장에서는 반별 제출을 2~3분씩 나누고 ZIP 수집은 제출이 끝난 뒤 진행하세요. 학생은 제출 완료를 확인할 때까지 사진 원본과 작성 글을 보관하고, 재시도는 같은 기기와 브라우저에서 진행하세요. 학번 입력 자체는 재학생 인증을 보장하지 않습니다. 운영 계정의 D1·R2·Worker 사용량과 한도는 계정 관리자가 행사 전에 확인해야 합니다.

이미지와 외부 라이브러리 출처는 안내 화면의 사진 설명과 `public/vendor/`의 라이선스 파일에서 확인할 수 있습니다.
